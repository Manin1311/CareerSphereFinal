Core AI — Master Orchestrator

Central Brain

Sabka master controller. Yeh decide karta hai kaun sa agent kab chalega. Multiple LLM providers ko rotate karta hai — agar ek fail ho toh automatically dusra try karta hai.

Kya Karta Hai
  • Sabka master controller — kaun sa agent kab chalega decide karta hai
  • Multiple LLM providers ko rotate karta hai (Gemini, OpenAI)
  • Ek API fail ho toh automatically dusra try karta hai (fallback)
  • Sab agents ke results combine karta hai
Multi-LLM Fallback Strategy
  • Primary: Gemini 2.5 Flash (Google)
  • Fallback 1: GPT-4o Mini (OpenAI)
  • Fallback 2: Groq LLaMA 3.3 70B
  • Round-robin rotation for multiple API keys

Parsing Agent

agents/parsing_agent.py · ResumeParsingAgent

Step 1 of Pipeline

Resume file (PDF / DOCX / TXT) ko read karke structured JSON mein convert karta hai. Pipeline ka pehla aur sabse critical step — agar yeh galat ho toh sab galat hoga.

Step 1 — Text Extraction
  • PDF: pdfplumber se text + PyMuPDF (fitz) se embedded photo extract karta hai
  • DOCX: python-docx se paragraphs + tables read karta hai
  • TXT: Direct file read
  • Text < 50 chars ho toh invalid file, empty result return karo
Step 2 — LLM Parsing
  • Extracted raw text + JSON schema LLM ko bhejte hain
  • LLM ko instruction: "Is text se ye specific fields nikalo"
  • LLM return karta hai perfectly structured JSON
  • JSON validate hota hai, fail hone par regex fallback
parsing_agent.py — LLM Schema
# Ye JSON schema LLM ko instruction ke roop mein diya jaata hai
SCHEMA = {
  "name": string, "email": string|null, "phone": string|null,
  "total_experience_years": float,
  "skills": [{ "skill": str, "years": float, "level": "beginner|intermediate|expert" }],
  "experience": [{ "company": str, "role": str, "duration_months": int }],
  "education": [{ "institution": str, "degree": str, "cgpa": float }],
  "projects": [{ "name": str, "tech_used": [str] }]
}

Skill Extraction Agent

agents/normalization_agent.py · 320+ Skills Dataset

Step 2 of Pipeline

Parsed skills ko standardize karta hai. "ReactJS", "React.js", "React JS", "react" — sab ek hi skill ke alag naam. Yeh agent unhe canonical (standard) form mein convert karta hai taaki baad mein accurate matching ho sake.

320-Skill Master Dataset
  • 320 canonical skills ka hardcoded dictionary
  • Har skill ke liye 15–30+ aliases defined hain
  • 20 domains: Programming, Web, DB, DevOps, ML, Mobile, Security, BI, etc.
  • Case-insensitive matching (ReactJS = reactjs = REACTJS)
3-Layer Matching Logic
  • Layer 1: Exact alias match (fastest path)
  • Layer 2: Lowercase + punctuation strip karo, phir match karo
  • Layer 3: Fuzzy string matching for typos
  • Koi match nahi mila? Skill as-is rakhte hain

Semantic Matcher

agents/matching_agent.py · SemanticMatchingAgent

Step 3 of Pipeline

Job description ki required skills aur candidate ki skills ko meaning ke level par compare karta hai. Sirf keyword match nahi — vector-based semantic similarity. "Machine Learning" aur "ML" ko same samajhta hai!

Layer 1 — Sentence Embeddings
  • sentence-transformers model skills ko 768-dim vectors mein convert karta hai
  • Candidate skills aur Required skills — dono ke vectors bante hain
  • cosine_similarity se N×M similarity matrix calculate hoti hai
  • Har required skill ka best match dhundha jaata hai
  • Similarity > 0.72 → MATCH ✅
Layer 2 — TF-IDF Fallback
  • Agar embedding model available nahi hai (offline mode)
  • TfidfVectorizer with character n-grams (3–5) use karta hai
  • Character-level matching → typos bhi handle hoti hain
  • Similarity > 0.60 → Match!
  • Last resort: Simple substring match
matching_agent.py — Core Cosine Logic
# Step 1: Skills ko high-dimensional vectors mein convert karo
cand_emb = model.encode(candidate_skills) # shape: [n, 768]
req_emb  = model.encode(required_skills) # shape: [m, 768]

# Step 2: N×M cosine similarity matrix banao
sim_matrix = cosine_similarity(cand_emb, req_emb)

# Step 3: Har required skill ke liye candidate mein best match check karo
for i, req in enumerate(required):
  sims = sim_matrix[:, i]
  if np.max(sims) > 0.72: matched.append(req) # ✅ Match!
  else: missing.append(req) # ❌ No match
Semantic Matching Examples (Real Results)
Required: "Machine Learning" vs Candidate: "ML" → Similarity 0.89 — MATCH ✅
Required: "React" vs Candidate: "ReactJS" → Similarity 0.94 — MATCH ✅
Required: "Python" vs Candidate: "Java" → Similarity 0.21 — NO MATCH ❌
💡
Cosine Similarity Kya Hai? Do vectors ke beech ka angle measure karta hai. 1.0 = identical meaning, 0.0 = completely different. 0.72+ hone par hum confidently keh sakte hain ki dono skills semantically same hain.

ATS Scorer

agents/matching_agent.py — Weighted Formula + ML Layer

Step 4 of Pipeline

Candidate ka final Match Score (%) calculate karta hai ek weighted formula se. Plus ek special ML Adaptive Layer jo historical hiring data se seekhta hai aur score improve karta hai!

Weighted Scoring Formula (Recruiter-Configurable)
Final Score = (Skill Score × 0.50) + (Experience Score × 0.30) + (Location Score × 0.20)
Score Calculation
  • Skill Score: Matched Skills ÷ Required Skills × 100 (+ experience bonus for 3+ years)
  • Experience Score: Candidate Years ÷ Min Required Years × 100 (max 100)
  • Location Score: Location match kiya? 100 : 30 (fallback)
  • Recruiter khud weights customize kar sakta hai dashboard se
ML Adaptive Layer
  • 10+ hired/rejected records DB mein hain?
  • RandomForestClassifier in-memory train hota hai
  • Features: [skill_score, exp_score, loc_score]
  • Output: Hired probability (0-100%)
  • Final = 80% formula score + 20% ML prediction

🧠 ML Adaptive Learning — Ek Unique Feature!

# Historical data se RandomForest train karo (in-memory, real-time)
past_apps = JobApplication.objects.filter(status__in=["hired", "rejected"])
if past_apps.count() >= 10: # Minimum 10 records needed to train
  clf = RandomForestClassifier(n_estimators=50, random_state=42)
  clf.fit(X, y) # X=[skill,exp,loc scores], y=[1=hired, 0=rejected]
  hired_prob = clf.predict_proba([[sk, ex, lc]])[0][1] * 100

# 80% manual weighted formula + 20% ML prediction = best of both worlds!
final_score = 0.8 * manual_score + 0.2 * hired_prob

Realtime Ranking Agent

Celery Workers + Redis + React Query Polling

Step 5 of Pipeline

Jaise hi koi nayi resume upload hoti hai, turant background mein processing start ho jaati hai. Recruiter ka leaderboard automatically live rehta hai — page refresh ki zarurat nahi!

Backend — Celery Workers
  • Resume upload → Django turant Celery task queue mein task push karta hai
  • Celery worker (background process) task uthata hai aur process karta hai
  • Parse → Normalize → Score → DB save — sab background mein
  • Leaderboard automatically score descending order mein sorted rehta hai
Frontend — React Query Polling
  • Frontend har 15 seconds mein backend se fresh data fetch karta hai
  • React Query stale-while-revalidate pattern use karta hai
  • Nayi candidate aate hi leaderboard automatically update ho jaata hai
  • User ko manual page refresh nahi karna padta
Celery Task + React Query Flow
# 1. Resume upload → Celery task queue mein push (user ko instant response milta hai)
parse_and_score_resume.delay(candidate_id, session_id)

# 2. Celery worker background mein process karta hai (async)
@shared_task
def parse_and_score_resume(candidate_id, session_id):
  parsed    = await parsing_agent.parse(file_path)
  normalized = normalization_agent.normalize(parsed.skills)
  score     = await matching_agent.match(normalized, criteria)
  Candidate.objects.filter(id=candidate_id).update(match_score=score)

# 3. Frontend har 15s mein leaderboard auto-refresh karta hai
useQuery({ queryKey: ['leaderboard', sessionId], refetchInterval: 15000 })
💡
Celery Kyu? Resume parsing ek heavy operation hai (2-5 seconds per file). Agar synchronously karo toh API request hang ho jayegi. Celery background mein kaam karta hai — user ko instant upload confirmation milta hai, aur processing quietly chal rahi hoti hai.

Interview AI Agent

agents/interview_agent.py · Groq LLaMA 3.3 70B

Job Seeker Portal

Job Seeker portal mein candidates ke liye AI-powered Mock Interviews conduct karta hai. Candidate ka resume + job description le ke role-specific questions generate karta hai, phir answers real-time evaluate karta hai.

3 Interview Modes
  • Technical Round: Architecture, coding, deep tech questions. Senior Tech Lead persona. Difficulty: 1 easy warmup, rest medium-hard.
  • HR Round: Behavioral, situational, CTC expectations, notice period. HR Manager persona.
  • Screening Round: Resume claims validation, basic eligibility check. Talent Acquisition persona.
Smart Question Generation
  • Recruiter manual questions + AI generated = Total set
  • AI sirf remaining quota fill karta hai (e.g. recruiter ne 2 diye, total 5 → AI 3 banayega)
  • AI koi bhi topic repeat nahi karta jo manual questions mein already covered hai
  • Questions candidate ke resume projects aur skills se directly linked hoti hain

Evaluator Viva Questions & Technical Answers

Comprehensive cheat sheet covering architecture decisions, algorithms, failure handling, and scalability defense for project presentations.

Q1 Why did you choose a Multi-Agent AI architecture over a single monolithic LLM prompt?
Answer: Monolithic prompts suffer from context fragmentation, high token latency, and unpredictable output schemas. By decoupling into specialized agents (Parsing Agent, Inference Agent, Scoring Agent, Interview Agent), each agent uses concise system prompts, operates with tight JSON schemas, runs in parallel, and saves up to 60% in total LLM token costs.
Q2 How does CareerSphere handle two-column or complex graphic PDF resumes without scrambling text?
Answer: We engineered a 3-tier fallback parser inside AdvancedAtsParsingAgent. Tier 1 performs vertical coordinate projection using PyMuPDF blocks (fitz), detecting column split boundaries (best_x) between 25% and 75% page width. If bounding boxes cut across columns, Tier 2 runs standard plain text streams, and Tier 3 uses pdfplumber for font-embedded vectors.
Q3 How is candidate match score calculated, and how do recruiters control evaluation criteria?
Answer: Match scores use a dynamic weighted vector sum: Score = (Skills * W_skills) + (Exp * W_exp) + (Loc * W_loc). Recruiters can customize weights (e.g. 50% skills, 30% experience, 20% location) per session. The system evaluates both exact skill overlaps and semantic skill matches parsed by the Inference Agent.
Q4 How do you handle Gemini API rate-limits and token quota exhaustion?
Answer: We implemented RotateLLMClient, a thread-safe singleton class that maintains a round-robin pool of multiple Gemini API keys. If an HTTP 429 Rate Limit or error occurs, the client automatically rotates to the next active key with exponential backoff retries, ensuring 99.99% system availability.
Q5 How are heavy AI tasks handled without freezing the React frontend UI?
Answer: All heavy parsing, skill extraction, and scoring jobs are offloaded asynchronously to Celery background workers backed by a Redis message broker. The React frontend receives a job task ID immediately and polls status endpoints (or handles WebSockets/events), maintaining a responsive 60fps user experience.
Q6 Why use JSONB fields in PostgreSQL alongside relational tables?
Answer: Resumes and job rubrics have highly variable schema attributes (variable numbers of projects, certifications, languages, custom weight maps). Storing these in PostgreSQL JSONB fields grants document-database flexibility while preserving relational integrity (foreign key cascades, indexed UUIDs) for accounts and job sessions.

Backend Overview
The CareerSphere backend is a Django 4.x application exposing a fully RESTful JSON API via Django REST Framework (DRF). It uses a function-based view (FBV) architecture with manual JWT authentication decorators (@require_seeker_jwt, @require_recruiter_jwt) instead of class-based DRF views, giving full control over request handling. All heavy AI and email tasks are offloaded to Celery workers backed by a Redis message broker, keeping HTTP response times under 300ms even during LLM inference operations.

JWT Authentication Architecture
CareerSphere implements custom JWT authentication without using Django REST Framework's built-in token auth or third-party libraries like SimpleJWT. Access tokens are generated using PyJWT with HS256 algorithm, carrying claims: user_id, role, email, exp. Two separate auth flows handle job seekers (seeker_auth.py) and recruiters/companies (recruiter_auth.py).

🔐 Seeker Authentication Flow

Register: POST /api/seeker/register/ → hashes password with Django's PBKDF2, creates JobSeekerAccount, sends OTP email.

Login: POST /api/seeker/login/ → verifies hash, returns JWT access (24h) + refresh (30d) tokens.

Protected routes use @require_seeker_jwt decorator which decodes the Bearer token and attaches the seeker object to the request.

🏢 Recruiter Authentication Flow

Register: POST /api/recruiter/register/ → creates Company record + default APIKey pair (public + secret key).

Login: POST /api/recruiter/login/ → same JWT pattern.

API key auth also supported: external resume ingestion via X-API-Key header authenticated in apikey_auth.py.

Auth Decorator Implementation
Python — seeker_auth.py import functools import jwt from django.http import JsonResponse from api.models import JobSeekerAccount def require_seeker_jwt(view_func): """Decorator: validates seeker JWT and injects seeker object into request.""" @functools.wraps(view_func) def wrapper(request, *args, **kwargs): auth_header = request.META.get('HTTP_AUTHORIZATION', '') if not auth_header.startswith('Bearer '): return JsonResponse({'error': 'Authentication required'}, status=401) token = auth_header[7:] # Strip 'Bearer ' prefix try: payload = jwt.decode( token, settings.SECRET_KEY, algorithms=['HS256'] ) user_id = payload.get('user_id') if payload.get('role') != 'seeker': return JsonResponse({'error': 'Invalid role'}, status=403) seeker = JobSeekerAccount.objects.get(id=user_id, is_active=True) request.seeker = seeker except jwt.ExpiredSignatureError: return JsonResponse({'error': 'Token expired'}, status=401) except (jwt.InvalidTokenError, JobSeekerAccount.DoesNotExist): return JsonResponse({'error': 'Invalid token'}, status=401) return view_func(request, *args, **kwargs) return wrapper

Request-Response Lifecycle (Resume Application)
1
HTTP Request arrives at Django Multipart POST with resume file or JSON application payload hits Django's WSGI server (Gunicorn in production). CORS middleware validates the Origin header against ALLOWED_ORIGINS list.
2
@require_seeker_jwt decorator runs JWT decoded from Authorization header. If valid, seeker object fetched from SQLite DB and attached as request.seeker. Invalid/expired tokens return HTTP 401 immediately without entering view logic.
3
View function executes seeker_resume.py receives file, saves to media/ directory, creates IngestJob record in DB, then dispatches Celery task: parse_resume_async.delay(ingest_job_id, file_path).
4
Immediate HTTP 202 Accepted returned Frontend receives task_id immediately. Django view has already returned. Heavy processing happens asynchronously in the Celery worker process — completely separate from the web server process.
5
Celery Worker: AdvancedAtsParsingAgent runs Worker picks up task from Redis queue. Column-aware PDF extraction runs. LLM (Gemini via RotateLLMClient) converts text to structured JSON. Candidate's resume_data field updated in SQLite.
6
Frontend polls for completion React polls /api/seeker/ats-status/?task_id=XYZ every 2 seconds. When status == "completed", the ATS score and parsed resume JSON are fetched and displayed to the user.
Celery Async Task System
Python — celery_worker.py from celery import Celery # Configure Celery to use Redis as both broker and result backend app = Celery('careersphere') app.config_from_object('django.conf:settings', namespace='CELERY') # CELERY_BROKER_URL = 'redis://localhost:6379/0' # CELERY_RESULT_BACKEND = 'redis://localhost:6379/0' @app.task(bind=True, max_retries=3) def parse_resume_async(self, ingest_job_id, file_path, session_id): """ Async task: Parse a resume PDF and compute match score. Runs in worker process, not in the web server process. """ try: from agents.advanced_ats_parsing_agent import AdvancedAtsParsingAgent from agents.matching_agent import SemanticMatchingAgent agent = AdvancedAtsParsingAgent() raw_text = agent.extract_text_column_aware(file_path) parsed_data = agent.parse_resume(raw_text) # Compute match score against job session criteria session = Session.objects.get(id=session_id) matcher = SemanticMatchingAgent() match_result = matcher.match(parsed_data, session.criteria) # Persist results to DB IngestJob.objects.filter(id=ingest_job_id).update( status='completed', completed_at=timezone.now() ) return match_result except Exception as exc: raise self.retry(exc=exc, countdown=30) # Retry after 30s
🔧 Production Deployment Note

In production, the Django server (Gunicorn), Celery workers, and Redis broker run as separate processes. The run.bat / install.bat scripts manage starting all three components. Celery workers can be scaled horizontally by launching additional worker processes that connect to the same Redis broker, enabling true parallel resume processing.

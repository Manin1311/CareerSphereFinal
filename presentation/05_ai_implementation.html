Multi-Agent System Architecture
CareerSphere features an ecosystem of 21 specialized AI agents located in backend/agents/. Instead of relying on a single monolithic prompt, each agent is a modular Python module designed for a single domain task — from parsing geometry-aware PDF resumes to computing semantic vector embeddings, generating adaptive interview questions, scoring candidate answers, and predicting hire probability via machine learning.

RotateLLMClient (LLM Key Rotation & Fallback)
backend/agents/llm.py (665 lines)
Infrastructure

The backbone of CareerSphere's reliability. LLM providers enforce tight rate limits (e.g. Gemini Free Tier = 20 Requests/Day per project). RotateLLMClient manages pools of Gemini and Groq API keys with intelligent failover.

  • Lazy Reset (Pacific Time): Aligns with Google Cloud's midnight PT quota reset cycle. Resets daily_usage automatically when a new day starts in PT.
  • 429 Handling & Retry-After Parser: Parses error messages like "Please try again in 43m41s" to mark keys as temporarily exhausted.
  • Per-Agent Provider Configuration: AgentModelConfig in DB maps each agent to its primary (e.g., Gemini) and fallback (e.g., Groq) provider.

Advanced ATS Parsing Agent
backend/agents/advanced_ats_parsing_agent.py (37KB)
Layout & Vision

Traditional text extractors read PDF text sequentially left-to-right, completely scrambling two-column resume layouts. AdvancedATSParsingAgent solves this through geometry-aware bounding-box detection.

  • Column Splitter: Uses PyMuPDF (fitz) to extract text blocks with bounding-box coordinates (x0, y0, x1, y1). Sorts text left-to-right column-wise before top-to-bottom.
  • 3-Tier Fallback Chain: PyMuPDF Column-Aware → pdfplumber → Raw PyMuPDF Text.
  • LLM JSON Structuring: Sends cleaned text to Gemini with strict JSON schema instructions for structured output.

Semantic Matching Agent
backend/agents/matching_agent.py (211 lines)
Scikit-Learn & ML

Evaluates candidates against job criteria using a multi-tiered mathematical scoring model:

  • Skill Score (Cosine Similarity): Embeds skills using sentence-transformers (all-MiniLM-L6-v2). Computes cosine similarity matrix. Matches skills above 0.72 threshold.
  • TF-IDF Char-N-Gram Fallback: If embeddings fail, uses TF-IDF character n-grams (3-5) with 0.60 similarity threshold to catch spelling variations.
  • Weighted Formula: Final = (Skill × 0.5) + (Experience × 0.3) + (Location × 0.2).
  • Historical ML Adjustment: If ≥10 historical applications exist, trains a RandomForestClassifier on past hiring data and blends 20% ML probability into the final score.

End-to-End AI Processing Flow
1
PDF Extraction (AdvancedATSParsingAgent) PyMuPDF analyzes physical text coordinates to cleanly parse 2-column resume structures into linear text without sentence fragmentation.
2
LLM Extraction (RotateLLMClient) Cleaned text sent to Gemini 2.5 Flash. Key manager selects active key with available quota. Returns structured JSON containing contact info, work history, and raw skills list.
3
Skill Normalization (NormalizationAgent) Raw skill strings mapped to canonical taxonomy. E.g., "React.js", "ReactJS", "React Native" are normalized with experience years computed per skill.
4
Semantic Vector Matching (SemanticMatchingAgent) Sentence-transformers generates 384-dimensional embeddings for candidate skills and job requirements. Cosine similarity score generated.
5
ML Predictive Scoring (RandomForest) RandomForest model evaluates overall profile against historical hired/rejected decisions to calculate a hiring probability percentage.
💡 Key System Guarantee

Thanks to the fallback architecture (Gemini → Groq → TF-IDF → Substring), CareerSphere's AI agents never fail completely. If an API key hits rate limits or internet connectivity degrades, the system automatically falls back to local mathematical algorithms (TF-IDF & character n-grams), ensuring 100% platform uptime.
